# 装机模拟器（代号：PC-Architect）项目设计总规格书

---

## 1. 项目概述

### 1.1 核心定位
本项目是一款面向硬核 DIY 爱好者与策略解谜玩家的**单机向装机模拟游戏**。游戏剥离繁琐的“手动拧螺丝/插拔线材”操作，聚焦于**“预算控制 + 物理空间干涉 + 协议逻辑校验 + 性能与美学平衡”**的装机核心乐趣。

### 1.2 核心体验支柱
1. **所见即所得的空间约束**：3D 自由视角直观展示硬件尺寸与碰撞干涉，配合 2D 工程图解精确标定毫米级冲突与接口拓扑。
2. **严谨且幽默的硬件逻辑**：基于真实硬件物理参数与协议规则构建数据，辅以恶搞品牌与奇葩硬件特性制造策略抉择。
3. **拒绝唯性能论的多维评价**：通过六维雷达图与动态场景权重，迫使玩家在性能、性价比、散热、静音、颜值与稳定性之间寻找最优解。

### 1.3 技术架构分工
| 层级 | 技术栈 | 核心职责 |
| :--- | :--- | :--- |
| **表现与交互层** | Godot（纯 C#） | 3D 参数化模型生成/缩放、自由相机控制、3D AABB 碰撞可视化、2D 剖面图解与雷达图 UI 渲染 |
| **规则与仿真层** | TypeScript（编译后由解释器执行） | 硬件兼容性校验、带宽降级计算、热力学/噪声平衡仿真、木桶效应与六维评分公式、关卡胜负与售后判定 |
| **数据驱动层** | JSON | 硬件静态参数库、协议兼容矩阵、恶搞文案库、关卡订单配置、二手市场刷新品池 |

## 2. 视觉与交互规范

### 2.1 3D 视口规范（空间参考）
* **交互方式**：支持围绕机箱中心点自由旋转（Orbit）、平移（Pan）、缩放（Zoom），支持一键切换正视/侧视/俯视视角，支持机箱侧板透明化或隐藏。
* **参数化模型生成（无须逐一手工建模）**：
  * 按硬件大类制作基础母版 Mesh（如：ATX/ITX 主板基板、单/双/三风扇显卡模板、单塔/双塔风冷、冷排+冷头、电源盒）。
  * 运行时根据 JSON 中的 `dimensions: [L, W, H]`（单位：mm）自动缩放模型外框，并按硬件数据定义的数量与锚点布置风扇和内存插槽。
* **冲突可视化**：当物理干涉发生时，相交的两个硬件在 3D 空间内生成高亮半透明红色包围盒（Wireframe + Overlay），并实时指示冲突区域。

### 2.2 2D 图解与 HUD 规范（精确分析）
* **2D 剖面图解覆盖层**：提供机箱内部空间的正交投影轮廓线，标出关键限位线（如显卡限长线、风冷限高线、冷排厚度边界），在发生冲突时显示精确差值（例：`冲突 +6mm：内存高度 48mm > 散热器避让 42mm`）。
* **接口拓扑与警告面板**：按 `BLOCKED`（红色阻断）/ `DEGRADED`（黄色降级警告）/ `OPTIMAL`（绿色正常）三级状态分类展示当前配置诊断结果。
* **六维评分雷达图**：完成规定负载测试后显示六个独立评级与 100 分基准环；配置发生变更后，标记上次测试结果为“待复测”状态。

## 3. 硬件数据与恶搞设定规范

### 3.1 硬件分类目录
系统包含以下 **8 类核心硬件**与 **1 类可选附件**：
1. **机箱 (Case)**：决定主板版型支持、风道布局、自然通风下限、各部位物理限位、前置 IO 规格、默认风扇位。
2. **主板 (Motherboard)**：决定 CPU 插槽、供电相数（VRM 承载能力）、内存代数与逐槽锚点/通道、PCIe/M.2 插槽及共享通道规则、板载接口。
3. **处理器 (CPU)**：决定插槽类型、单核/多核基准算力、核显性能、内存控制器支持频率、PL1/PL2 功耗与发热量、是否自带原装散热。
4. **显卡 (GPU)**：决定长度/厚度（占槽数）/高度、PCIe 版本与电气通道数、算力、显存容量、持续与瞬时峰值功耗、供电接口需求。
5. **内存 (RAM)**：决定代数（DDR4/DDR5）、单条容量、频率/时序、马甲高度（mm）、是否支持 RGB。
6. **存储 (Storage)**：决定形态（M.2 2242/2280、2.5" SATA、3.5" HDD）、协议（NVMe PCIe 3/4/5、SATA）、容量、读写性能、发热量。
7. **散热器 (Cooler)**：分风冷（塔高、单/双塔、热管数、基准热阻、风扇可调偏移量、内存避让区）与水冷（冷排尺寸 120/240/360、冷排+风扇总厚度、基准热阻、水泵噪声）。
8. **电源 (PSU)**：决定长度/规格（ATX/SFX）、持续承载功率、短时承载功率、建议峰值上界、转化效率等级（白牌至钛金）、模组类型（非/半/全模组）、自带线材接口数量（24Pin, CPU 8Pin, PCIe 8Pin, 12V-2x6）。
9. **机箱风扇 (Case Fan)** *(可选附件)*：尺寸（120/140mm）、风量（CFM）、风压、噪声（dBA）、RGB 属性。

### 3.2 恶搞品牌命名与特性映射参考
所有参数严格对标现实硬件（价格、功耗、尺寸、性能比例），品牌采用谐音/梗化命名：

| 现实原型 | 恶搞品牌名 | 品牌人设与硬件设计倾向 |
| :--- | :--- | :--- |
| Intel | **Incel / 挤牙膏科技** | 单核强、多核功耗爆炸（大火炉）、频繁换接口（主板不通用） |
| AMD | **AYM / 战未来半导体** | 积热明显、接口长寿（老主板刷 BIOS 也能用）、X3D 游戏特化 |
| NVIDIA | **Nvidya / 刀法精工** | 光追与 AI 算力强、显存极其抠门（低端卡配 8G 显存）、瞬时功耗高 |
| AMD Radeon | **Radon / 矿老板之友** | 性价比极高、功耗偏高、部分型号尺寸巨无霸、二手市场高发区 |
| ASUS ROG | **ROUGE / 败家之眼** | 颜值/灯效拉满、供电豪华、同规格溢价 50%（专坑预算有限玩家） |
| Noctua | **Noc-Owl / 屎黄静音坊** | 极致静音与解热、无任何 RGB 灯光、固定屎黄色（极易破坏纯白/纯黑颜值分） |
| 杂牌/山寨 | **Boom-Power / 烈士墙** | 价格极低、虚标功率（实际持续承载显著低于标称铭牌）、带隐藏故障风险 |

### 3.3 关键 JSON Schema 约定（概念结构）
* **机箱插槽与空间锚点**：每个安装位定义局部原点 `anchor: [x, y, z]` 与最大空间 `max_bounds: [L, W, H]`。
* **多包围盒定义（以双塔风冷为例）**：
  * `body_aabb`：散热器主体（塔体）占位。
  * `fan_aabb`：前置风扇占位，附带 `adjustable_y_max: 15`（允许上移最多 15mm 以避让内存，但同步增加整机散热器总高度）。

## 4. 兼容性与约束引擎规范

每次硬件变更后，TypeScript 规则引擎执行全量检查，输出三态结果：

### 4.1 状态分级定义
* **`BLOCKED`（红色阻断）**：需明确标明阻断所处阶段：
  * **装配阶段阻断**：缺少必要部件、接口不符或物理空间干涉时，允许继续编辑配置，但须修复后方可运行正式负载测试。
  * **测试阶段阻断**：装配检查通过但在规定负载测试中触发电源保护断电时，测试失败并禁止交付。
  * **沙盒例外**：沙盒模式支持强制装配以供观察，但未通过正式测试的配置不出具正式评级。
* **`DEGRADED`（黄色降级警告）**：物理可安装且能通过测试点亮，但存在性能损失、通道降级或稳定性余量不足，直接反映在雷达图扣分或售后风险中。
* **`OPTIMAL`（绿色正常）**：完全兼容且无性能与稳定性损耗。

### 4.2 物理空间干涉规则
1. **机箱容纳校验**：
   * 主板版型 $\in$ 机箱支持列表（`ITX < mATX < ATX < E-ATX`）。
   * 显卡长度 $\le$ 机箱显卡限长（若前置安装水冷排，需扣除冷排+风扇厚度：$\text{有效限长} = \text{基础限长} - \text{前冷排总厚}$）。
   * 显卡厚度（占槽数）与长度不与底部电源仓/水冷排碰撞。
   * 风冷高度（含风扇上移量）$\le$ 机箱风冷限高。
   * 电源长度 $\le$ 机箱电源仓限长（需为非模组/半模组电源额外预留 20mm 藏线空间）。
2. **局部硬件干涉矩阵（重点机制）**：
   * **风冷与内存**：主板逐槽记录位置、通道和安装锚点。规则引擎对已装内存与塔体、偏移后的风扇分别进行包围盒检查；3D 视口与 2D 剖面图共用同一套坐标与诊断结果。移动风扇时按最高部件重算侧板余量，换槽时按实际通道重算有效带宽。边界刚好接触且无穿透（距离 $= 0$）视为合法容纳。
   * **顶部水冷 vs 主板供电散热片 / 内存**：顶部安装 240/360 冷排时，检查主板顶部边界预留厚度是否大于冷排总厚。

### 4.3 协议与接口逻辑规则
| 校验项 | 匹配规则 | 冲突处理逻辑 |
| :--- | :--- | :--- |
| **CPU 插槽** | `CPU.socket === MB.socket` | 不匹配 $\rightarrow$ `BLOCKED` |
| **芯片组供电/代际** | 检查 CPU 满载功耗是否超出主板 VRM 承载上限 | 超出 $\rightarrow$ `DEGRADED`（触发供电过热降频警告） |
| **内存代数** | `RAM.family === MB.ram_family`（DDR4/DDR5 严格互斥） | 不匹配 $\rightarrow$ `BLOCKED` |
| **内存通道与频率** | 按实际占用的通道、插槽和控制器支持频率计算有效带宽 | 带宽下降提示 `DEGRADED`，按目标负载计算实际性能损失 |
| **PCIe 协议版本** | `PCIe` 同族协议向下/向上兼容 | 版本不匹配 $\rightarrow$ 取两者最小值计算带宽；若有效带宽低于设备需求的 70%（如 PCIe 4.0 x8 显卡插在 3.0 主板），触发 `DEGRADED` 并扣性能分 |
| **通道共享抢占** | 检查主板 `shared_with` 字段（如插满 2 条 M.2 导致显卡槽从 x16 降为 x8，或禁用某些 SATA 口） | 触发抢占 $\rightarrow$ 若被禁用接口已插设备则 `BLOCKED`；显卡降通道则 `DEGRADED` |
| **供电接口数量** | 统计 PSU 拥有的 `CPU 8Pin`、`PCIe 8Pin`、`12V-2x6` 数量 vs 主板与显卡需求总和 | 线材数量不足 $\rightarrow$ `BLOCKED`（无法供电）；若允许使用合规转接线 $\rightarrow$ `DEGRADED` |

### 4.4 功耗与电源负载规则
* **持续负载 ($P_{\text{持续}}$)**：合计规定负载下 CPU、GPU 与其他设备的持续功耗（W）。
* **瞬时峰值负载 ($P_{\text{峰值}}$)**：按同一测试曲线计算同时出现的最大总瞬时功耗（W）。
* **电源承载参数**：每款电源在 JSON 中定义实际持续承载 $W_{\text{持续}}$、对应测试脉冲时长的短时承载 $W_{\text{短时}}$，以及建议峰值上界 $W_{\text{建议}}$（其中 $W_{\text{建议}} < W_{\text{短时}}$）。
* **判定逻辑**：
  * 若 $P_{\text{持续}} > W_{\text{持续}}$ 或 $P_{\text{峰值}} > W_{\text{短时}}$：测试中触发电源保护关机，判定为 `BLOCKED`。相同配置与负载应严格复现相同结果。
  * 其余情况下若 $P_{\text{峰值}} > W_{\text{建议}}$：测试通过，判定为 `DEGRADED`，记录峰值余量偏低；若处于启用售后的模式，则相应提高重启报修概率。
  * 其余情况均通过本项检查。

## 5. 仿真与多维评分模型

完成规定负载测试后，系统生成**六维雷达图**、**各维分数及独立评级**与**加权总分**。100 分为基准环，所有维度均允许突破 100 分。

### 5.1 核心物理仿真（木桶与热平衡）
1. **木桶瓶颈系数 ($K_{\text{bottleneck}}$)**：
   * 根据目标用途（如 1080p 高刷偏重 CPU，4K 游戏偏重 GPU，生产力偏重 CPU 多核与内存容量），对比 CPU、GPU 与内存带宽的相对档位。
   * 当某核心子系统算力显著滞后时，计算整机有效算力折损（例如弱 CPU 带旗舰卡，显卡有效算力发挥度降至 65%）。
2. **热平衡、温控调速与降频仿真（单向解析计算）**：
   * 机箱风道效率由进出风量平衡度决定（需有进有出，全出风/全进风或闷罐结构惩罚加重）；每种机箱配置正数自然通风下限，无机箱风扇时仍保持有限热阻（避免除零）。
   * 对 CPU、GPU 分别计算稳态温度：
     $$T_{\text{steady}} = T_{\text{ambient}} + P_{\text{heat}} \times R_{\text{eff}}$$
     其中有效热阻 $R_{\text{eff}} = \frac{R_{\text{base}}}{\text{AirflowEfficiency}}$（$R_{\text{base}}$ 为该散热方案在目标负载工况下的基准热阻）。例如环境 25°C、持续热功率 150 W、有效热阻 0.5°C/W 时，预测稳态温度为 100°C。
   * **单向温控与节流**：根据算出的 $T_{\text{steady}}$ 单向查表得出风扇最终转速与噪声（不反向修改 $R_{\text{eff}}$，避免循环求解）。当 $T_{\text{steady}} > T_{\text{throttle}}$（如 90°C）时，触发**热节流惩罚**：芯片性能按超温幅度衰减，且对应散热风扇转速强制拉满至 100%。

### 5.2 六维雷达图评分维度
1. **绝对性能 (Performance)**：经过`协议降速`、`木桶瓶颈`、`热节流`三大惩罚修正后的整机实际综合算力（结合当前任务用途计算）。
2. **性价比 (Value / ROI)**：
   $$\text{性价比分} = 100 \times \frac{\text{有效性能分} \div \text{配件计价总额}}{\text{同用途基准性能价格比}}$$
   * **计价口径**：购买件按实际成交价计入；神秘箱、沙盒及其他免费配件按场景参考价计入。参考价、计价总额与基准比均须严格为正数；装机费与维修费单独记账，不计入配件计价总额。
3. **散热 (Thermals)**：按规定负载下 CPU、GPU 距各自降频温度的安全余量评分，取两者中余量较小者作为主判定依据。
4. **静音 (Acoustics)**：按同一负载下整机最终噪声（dBA）评分；温控触发风扇提速后，统一采用提速后的噪声值。低温高噪的机器可同时获得高散热分与低静音分。特定用途的散热与静音分分别由对应基准曲线换算。
5. **颜值与整洁度 (Aesthetics)**：
   * **色彩协调度**：统计所有可见硬件主色调，纯色系（全白/全黑）或统一主题色加分；出现突兀配色（如全白海景房中混入屎黄色风扇）扣分。
   * **RGB 协同**：全套无灯（极简风）或全套支持统一神光同步加分；不同品牌杂乱灯效扣分。
   * **空间饱满度**：主板版型与机箱大小匹配度（如 ATX 机箱装 ITX 主板扣分），三风扇大机箱装单风扇短卡扣分。
   * **理线整洁度**：全模组电源 > 半模组 > 非模组（非模组电源机箱内冗余线材扣颜值分及少量风道分）。
6. **稳定性 (Stability)**：
   * 按电源持续功率与瞬时峰值余量、主板 VRM 供电余量综合评估；高风险 `DEGRADED` 警告会拉低该项。电源转化效率认证（如金牌/白牌）本身不决定稳定性。
   * 剩余扩展槽、机箱容积或预算上限按订单明示条件单独验收，不混入雷达图维度；小体积专项挑战可另行展示“每升性能”。

* **逐维评级与总分计算**：
  * 各轴按用途基准换算成非负数，保留一位小数（四舍五入），再独立定级。首版评级阈值如下：`E` $[0, 40)$、`D` $[40, 55)$、`C` $[55, 70)$、`B` $[70, 85)$、`A` $[85, 100)$、`S` $[100, +\infty)$。
  * 整机总分使用上述六维已舍入数值按用途权重加权求和，按相同精度（保留一位小数）与阈值定级。
* **爆框显示规范**：六轴共用线性刻度并标出 100 分基准环。超出基准的顶点按实际分值向环外延伸，必要时等比例缩放整图并保留 100 分基准环。每轴独立展示数值与字母等级（例：`性能 125.0 · S`、`静音 68.0 · C`）。
* **边界验收基准**：`99.9` 评为 `A`，`100.0` 评为 `S`；`125.0` 的顶点半径为 100 分环的 `1.25` 倍；六轴等权且一轴 `130.0`、其余五轴均为 `70.0` 时，总分为 `80.0`（评级 `B`）。

### 5.3 委托验收、整机评分与客户反馈
* **委托验收**：订单列出预算和客户明确提出的要求（例如“至少 32 GB 内存”“指定这款显卡”）。整机通过必要的装机与运行测试检查，且满足全部明示条件，即可完成委托。交付前逐项显示达标情况，允许玩家随时调整配置；客户不设总分门槛。
* **整机评分**：按订单用途配置六维权重（权重之和为 `1.0`），将各维得分加权求和，展示总分与整机评级。同一用途下，客户的隐藏身份不改变机器的客观跑分。
* **客户反馈**：订单生成时随机抽取客户的“硬件熟悉程度”（如小白/极客），随订单保存且接单界面不予显示。小白客户对达到明示要求的机器表示满意；极客客户在验收通过后还会审视具体配置，若发现影响实际使用的选件短板，会指出具体零件与后果并给出差评（差评仍记为已完成委托）。
* **结算示例**：客户要求预算内配指定显卡和至少 32 GB 内存。玩家装了单条 32 GB 内存，机器可运行且预算达标。两类客户均验收通过，看到的客观评分相同；小白客户表示满意，而极客客户若检测到单通道带宽已限制目标负载，会指出“显卡是我要的，但你只装了一根内存，高刷游戏里它跑不满”。评价依据必须来自实际测试或规则诊断，单纯采购低价配件本身不构成偷工减料。

## 6. 游戏模式设计

### 全局规则：售后适用范围与时间推进
* **售后适用范围**：售后机制由产生原订单的游戏模式决定。当前默认仅 **§6.1 委托挑战模式**启用售后；§6.2 二手市场、§6.3 神秘箱、§6.4 故障诊断、§6.5 时代剧本与 §6.6 沙盒作为独立模式运行时均关闭售后（主线委托使用二手件时仍按主线规则处理）。关闭售后的模式在当前挑战结束时即完成结算，不生成后续工单、维护合同或返修费用。§6.4 的初始故障属于当前关卡题面，不计入售后。
* **时间与周期推进**：启用生涯流转的模式（§6.1 主线委托、§6.2 二手市场）采用离散的“经营周期（天/周）”推进机制。每次完成主线订单交付或手动点击“推进至下一周期”时，系统同步推演周期：结算到期的个人订单保修判定、触发到期的企业合同定期巡检工单，并刷新二手市场在售商品与价格波动。独立解谜与沙盒模式（§6.3–§6.6）不依赖时间推进。

### 6.1 委托挑战模式（主线解谜）
* **机制**：系统派发不同画像的虚拟客户订单（如：“宿舍党静音小钢炮”、“主播高颜值白海景房”、“视频工作室多盘位渲染机”、“极限预算网游主机”）。
* **核心乐趣**：通过客户设定的奇葩物理/功能/预算硬性条件，考验玩家对硬件冷门参数与兼容边界的掌握。

#### 订单呈现
客户只在单子上留几句简短要求，预算、数量和交付条件以结构化字段展示。硬件熟悉程度为隐藏属性，玩家可从措辞细节判断主要用途；游戏不设聊天、追问或议价界面，交付评价作为订单记录留档展示。企业或个人属于公开的订单类别，与客户硬件熟悉程度相互独立。

#### 交付与售后
* **售后工单**：交付时留存原订单、实际配置与测试结果。售后以关联原单的新工单形式出现，单上写明症状或服务要求。玩家可调阅交付记录，检查或更换配件并复测；结单后记录处理结果，后续周期判定沿用维修后的最新配置。
* **个人订单**：根据交付配置与用途的匹配程度、实际稳定性决定售后概率（例如长期渲染反复热降频引发性能投诉，电源瞬时余量不足引发重启报修）。风险仅源自对应的使用条件；配色、客户熟悉程度和整机总分不直接参与故障判定。订单明示有限保修期，在约定的游戏内使用周期结束时按对应风险判定一次；判定结果按设备、故障原因与周期保存，读档沿用，同一未结故障不重复派单。保修期满后停止抽取，已生成工单可继续处理。
* **企业订单**：服务器或批量采购可附带长期服务条款，订单提前列明服务期限、覆盖设备与约定事项。期限内可多次产生工单，包括按约定期巡检（即使配置完全稳定也需履约）与突发故障维修。批量采购工单会注明受影响的具体设备或批次，允许仅针对涉及的机器进行处理。
* **验收示例**：同一台高负载工作机改善散热后，在相同使用条件下因过热产生个人售后单的概率应明显降低；企业合同若约定两次巡检，第一次完成后合同仍保持有效，第二次按周期正常派单。

#### 订单收入与售后费用
* **交付结算**：普通个人委托明示配件预算上限并另列装机费，配件实报实销、预算结余归客户（例：上限 6000 元、采购 5600 元、装机费 200 元，客户实付 5800 元，本单返修前毛利 200 元）。在该规则下，玩家在普通委托中理应优先选用全新稳妥配件，仅在预算极限卡死、全新件无法达标时才被迫考虑二手件。企业批量单可明示固定总报价，按报价结算，由玩家承担采购成本并保留差额。后续维护收入与返修支出追记至原单；关闭售后的模式仅结算交付。
* **原方案返修**：以原单写明的用途和交付配置为依据。若诊断确认选件不当导致故障，由玩家承担修复所需配件成本并计入原单售后支出；客户的隐藏身份及好差评不影响费用归属。
* **新增需求**：客户在交付后提出扩容、升级或改变用途，超出原约定的部分另开独立付费订单，列明新要求、预算与报酬。玩家可从原单分别追溯返修损失与升级收益。
* **企业长期维护**：接单时列明服务范围、维护报酬、支付条件及备件费用承担方。按合同结算巡检或维修；已包含在维护报酬内的事项不重复结算。
* **验收示例**：企业原订 32 GB 渲染工作站，交付后在约定负载下因散热器选型不足而降频，同时客户希望升级到 64 GB。更换合适散热器的费用由玩家承担，新增内存另开付费升级单；结算时可从原单清晰追溯两笔记录，区分返修损失与升级收益。

### 6.2 二手捡漏与市场波动模式
* **机制**：商店拆分为“全新官方店”与“鱼塘二手市场”。二手商品价格为全新件的 30%~70%，随经营周期刷新库存并附带随机状态标签：
  * `成色极佳（箱说全）`：无负面效果。
  * `网吧退役/矿卡`：价格极低，但基础发热量 +15%，稳定性分数上限降低。
  * `战损/缺件`：如散热器缺少特定平台扣具、电源剪掉了一根 PCIe 供电线。
* **核心乐趣**：高风险高回报，利用二手件极大幅度拉升“性价比”维度分数（或作为主线极限预算订单的破局手段）。

### 6.3 给定硬件装机模式（神秘箱挑战）
* **机制**：锁定商店购买功能，直接发给玩家一箱指定的混合硬件（包含多个机箱、不同板型主板、若干长短不一的显卡、杂乱的内存与散热器）。
* **核心乐趣**：纯粹的空间排列组合与接口解谜，要求玩家从“一堆看似互相冲突的废铁”中拼出能开机且评分最高的主机。

### 6.4 救砖 / 赛博华佗模式（故障诊断）
* **机制**：加载一台**已经装好但存在严重问题**的故障主机（例：散热器挡住一半内存导致单通道、电源过载烤机黑屏、M.2 插槽抢占导致显卡降速、闷罐积热严重降频）。
* **限制条件**：给予极低改造预算，或限定“最多只能更换 2 个零件”。
* **核心乐趣**：通过观察 2D 报错与雷达图短板，精准定位瓶颈并用最小代价修复整机。

### 6.5 时代穿越主题模式（扩展剧本）
* **机制**：利用 JSON 中的 `era_year` 标签过滤商店库存，重现经典硬件困境（例：“2021 矿潮危机”——全网显卡溢价 250% 下的装机自救；“2017 内存暴涨时代”）。

### 6.6 沙盒模式
* **机制**：无限预算、全硬件图鉴解锁（支持切换“忽略物理/协议阻断强行组装”的娱乐开关），自由测试极限配置与跑分上限。

## 7. 数值与平衡性检验基准（验收标准）

在数据录入与规则调优阶段，系统需满足以下 4 项平衡性检验：
1. **“丐帮电源”反制验证**：给旗舰配置搭配便宜的虚标杂牌电源，综合总分与稳定性必须显著低于搭配优质金牌电源的配置；$P_{\text{峰值}}$ 超过 $W_{\text{建议}}$ 但未超过 $W_{\text{短时}}$ 且持续功耗合格时应判定为 `DEGRADED` 并仅提示风险，超过 $W_{\text{短时}}$ 时必须触发保护关机（测试阶段 `BLOCKED`）。
2. **“闷罐积热”反制验证**：无风扇全封闭玻璃机箱搭配高功耗 CPU+GPU，烤机测试必须触发热节流降频，导致其“性能轴”与“静音轴”双双暴跌，总分低于风道合理的低一档硬件配置。
3. **“大马拉小车”验证**：顶级显卡搭配入门级低端 CPU 时，性能轴得分必须因木桶瓶颈惩罚而大幅缩水，性价比轴得分坠底。
4. **“兼容性博弈”验证**：至少存在多组“高马甲内存 vs 双塔风冷”、“超长旗舰显卡 vs 前置 360 冷排”的典型冲突场景，能够被 3D/2D 系统准确拦截并给出清晰的调整路径（换矮马甲/换槽位/上移风扇/换水冷/换更大机箱）。
